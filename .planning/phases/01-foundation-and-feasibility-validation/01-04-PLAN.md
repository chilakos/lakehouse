    1. Create `etl/src/iceberg_utils/benchmark.py` -- Benchmark harness:
       - `BenchmarkResult` dataclass: query_name, engine (str), latency_ms (float), rows_returned (int), bytes_scanned (int | None), timestamp
       - `run_benchmark(conn, query: str, query_name: str, engine: str, iterations: int = 5) -> list[BenchmarkResult]` -- Runs query N times, records latency for each run. Discards first run as warmup.
       - `generate_benchmark_queries(namespace: str) -> list[dict]` -- Returns standard benchmark queries:
         - Full scan: `SELECT COUNT(*) FROM {ns}.trades`
         - Filtered scan: `SELECT * FROM {ns}.trades WHERE trade_date = DATE '2025-06-15'`
         - Aggregation: `SELECT symbol, SUM(notional) FROM {ns}.trades GROUP BY symbol`
         - Join (if positions table exists): `SELECT t.symbol, p.market_value FROM {ns}.trades t JOIN {ns}.positions p ON t.account_id = p.account_id`
         - Point lookup: `SELECT * FROM {ns}.trades WHERE trade_id = 42`
       - `format_results(results: list[BenchmarkResult]) -> str` -- Formats as markdown table for the benchmark report.
       - `save_results(results: list[BenchmarkResult], output_path: str) -> None` -- Saves to JSON file for later analysis.

    2. Create benchmark integration tests (`test_benchmarks.py`):
       - @pytest.mark.slow marker (not run in quick test suite)
       - test_benchmark_trino: Runs all benchmark queries against Trino, collects results, asserts all queries complete without error
       - test_benchmark_spark: Runs equivalent queries via PySpark, collects results
       - test_benchmark_comparison: Compares Trino vs Spark latencies, logs results (does not assert on performance -- just captures metrics)
       - Test creates trades table with 10,000 rows for meaningful benchmarks

    3. Create RBAC configuration (`infra/docker/trino/etc/access-control/rules.json`):
       - Per Research RBAC pattern:
         - "data_engineers" group: full access (SELECT, INSERT, UPDATE, DELETE) to all tables in iceberg catalog
         - "data_readers" group: SELECT-only on all tables
         - "data_admin" group: full access including schema operations
         - Sensitive namespace restriction: only "data_admin" can access "sensitive_ns" schema
       - Update `infra/docker/trino/etc/config.properties` to enable file-based access control (access-control.name=file, security.config-file path)

    4. Create RBAC integration tests (`test_rbac.py`):

       - test_engineer_can_write: Connect as engineer user, INSERT succeeds
       - Note: For local Docker testing, Trino file-based access control works without LDAP. Tests verify the rules.json is correctly applied.

       - Action items: Configure OTF, test connection, update ADR status to ACCEPTED with chosen option.
