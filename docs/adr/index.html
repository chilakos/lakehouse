Architecture Decision Records

17 records covering the lakehouse foundation (compute, governance, ingestion), the AI consumption layer (semantic plane, gateway, agent patterns), and the cross-cutting governance model. Listed in chronological order.

001
Teradata OTF + Nessie REST Catalog Feasibility
Feasibility assessment of Teradata Open Table Format with Nessie as the REST catalog backend. Informed ADR-003 and the subsequent decision to remove Teradata OTF from the catalog architecture.
Draft Teradata OTF Nessie Mar 2026 view .md →
002
Trino as the Mandatory Query Gateway for All Iceberg Access
All Iceberg table access must route through Trino as the federated SQL gateway. Direct engine access to storage is prohibited for user-facing queries. Establishes Trino as the primary on-prem interactive analytics engine.
Accepted Trino query gateway Mar 2026 view .md →
003
Teradata Decoupling Strategy — Dual-Write Migration to Iceberg
Strategy for decoupling from Teradata via dual-write migration pattern. Iceberg tables shadow Teradata tables; consumers migrate incrementally. Teradata OTF removed from catalog dependency.
Accepted Teradata migration Iceberg Mar 2026 view .md →
004
Trino Workload Isolation via Resource Groups
Trino resource groups partition query workloads into priority lanes — ETL, interactive analytics, AI/ML, and reporting — preventing runaway queries from starving critical workloads. Defines SLAs per lane.
Accepted Trino resource groups Mar 2026 view .md →
005
Use Trino + Python for Compute — No Apache Spark
Python is the transformation language for all ETL/ELT pipelines (not dbt, not Spark DAGs). Trino handles all SQL compute. Spark is available for cloud burst ML workloads on Databricks only.
Accepted Python Trino no Spark on-prem Mar 2026 view .md →
006
Retrieval-Augmented Schema Linking for NL-to-SQL at Scale
RAG-based schema linking resolves the NL-to-SQL scalability problem at tens of thousands of tables. Vector-embedded schema metadata retrieved at inference time — no full schema in prompt context.
Accepted NL-to-SQL RAG AI semantic layer Mar 2026 view .md →
007
Automated Governance Pipeline — OpenMetadata Classification to Ranger TagREST
Automated pipeline: OpenMetadata classifiers scan new tables → PII/PCI tags applied → Ranger TagREST policies propagate masking and access rules. No manual policy authoring for standard classification tiers.
Accepted OpenMetadata Ranger governance automation Mar 2026 view .md →
008
Microsoft Fabric OneLake — Shortcuts and XTable Not Adopted
OneLake Shortcuts and XTable (Delta↔Iceberg conversion) evaluated and rejected. Shortcuts create a dependent path that bypasses credential vending. XTable conversion adds latency and format mismatch risk. Position carried forward through ADR-010 → ADR-011 → ADR-014.
Superseded Fabric OneLake → ADR-010 → 011 → 014 Mar 2026 view .md →
009
AI Data Hub — RAG-Ready Data Serving Layer for the Lakehouse
Gold layer tables exposed to AI consumers via a Python FastAPI trust boundary enforcing certified query patterns. Direct Gold access prohibited for agent workloads — all AI queries must pass through the certified gateway. Foundational for ADR-015 (RBC Data Gateway).
Accepted AI hub FastAPI trust boundary Mar 2026 view .md →
010
Microsoft Fabric Import Semantic Model as BI and AI Surface Layer
Fabric Import mode (not DirectLake, not Shortcuts) as BI/AI surface. Superseded on 2026-04-15 by ADR-011 which adopts a phased approach with Snowflake Cortex in Phase 1.
Superseded Fabric Import mode → ADR-011 Apr 2026 view .md →

Snowflake Cortex as Access and Semantic Layer — Phased Fabric Extension
Phase 1: Snowflake Cortex Analyst over Gold Iceberg V2 via external volumes (zero-copy) as the AI semantic layer. Phase 2: Fabric as parallel BI/AI surface when OBIEE → Power BI migration completes. Supersedes ADR-010. Reframed by the amendment below; further amended by ADR-014.

013
Ingestion is a Platform Capability — Hubs Compose, They Do Not Ingest
Establishes the federation principle for the Lumina hub model: ingestion is a centralized platform capability owned by the lakehouse team. LOB-aligned hubs compose, conform, and curate from the shared raw zone — they do not run their own ingestion stacks. Removes the duplication risk of every hub building its own pipelines.
Proposed hubs federation ingestion Apr 2026 view .md →
014
Semantic Plane Architecture — Unified Semantic Layer Across Snowflake and Trino
Adopts Microsoft Fabric semantic models as the single enterprise semantic layer across both Snowflake (DirectQuery + Mirroring) and Trino (DirectQuery). Resolves the Cortex-vs-Fabric split: business definitions live in one place and AI agents reason against one surface, regardless of where data physically resides. Amends ADR-011.
Proposed Fabric semantic models unified semantic layer amends ADR-011 May 2026 view .md →
014amend
Amendment to ADR-014 — Gateway as Trust Boundary and Raw Zone Landing
Clarifies two points in ADR-014: the RBC Data Gateway (ADR-015) is the trust boundary for all agentic traffic to the semantic plane, and operational data lands in a hybrid Raw Zone owned by the platform before any hub composes from it.
Amendment amends ADR-014 gateway Raw Zone May 2026 view .md →
015
RBC Data Gateway — On-Prem Trust Boundary and Orchestrator for AI Data Access
FastAPI on OpenShift as the on-prem trust boundary for all AI traffic into the lakehouse. Orchestrates routing between Snowflake Cortex (tactical), Fabric semantic models (strategic), and Trino. Enforces Entra ID OBO, Immuta ABAC, and audit logging at a single chokepoint. Productionizes the FastAPI pattern from ADR-009 and ADR-011.
Proposed FastAPI trust boundary orchestrator May 2026 view .md →

017
Operational vs Collaborative Data Products — Two-Type Model and Accountability Framework
Adopts the two-type data product model from Steve Jones (Feb 2022). Operational Data Products are owned by business leaders of the originating area; Collaborative Data Products are managed by a Data Product Manager and accountable at the attribute level to contributing ODP owners. Introduces the attribute accountability map as a CDP release gate. Amends ADR-011, ADR-012, ADR-014 governance sections.
