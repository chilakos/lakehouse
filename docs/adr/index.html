001
Teradata OTF + Nessie REST Catalog Feasibility
Feasibility assessment of Teradata Open Table Format with Nessie as the REST catalog backend. Informed ADR-003 and the subsequent decision to remove Teradata OTF from the catalog architecture.

002
Trino as the Mandatory Query Gateway for All Iceberg Access
All Iceberg table access must route through Trino as the federated SQL gateway. Direct engine access to storage is prohibited for user-facing queries. Establishes Trino as the primary on-prem interactive analytics engine.
Accepted Trino query gateway Mar 2026 view .md →
003
Teradata Decoupling Strategy — Dual-Write Migration to Iceberg
Strategy for decoupling from Teradata via dual-write migration pattern. Iceberg tables shadow Teradata tables; consumers migrate incrementally. Teradata OTF removed from catalog dependency.
Accepted Teradata migration Iceberg Mar 2026 view .md →
004
Trino Workload Isolation via Resource Groups
Trino resource groups partition query workloads into priority lanes — ETL, interactive analytics, AI/ML, and reporting — preventing runaway queries from starving critical workloads. Defines SLAs per lane.
Accepted Trino resource groups Mar 2026 view .md →
005
Use Trino + Python for Compute — No Apache Spark
Python is the transformation language for all ETL/ELT pipelines (not dbt, not Spark DAGs). Trino handles all SQL compute. Spark is available for cloud burst ML workloads on Databricks only.
Accepted Python Trino no Spark on-prem Mar 2026 view .md →
006
Retrieval-Augmented Schema Linking for NL-to-SQL at Scale
RAG-based schema linking resolves the NL-to-SQL scalability problem at tens of thousands of tables. Vector-embedded schema metadata retrieved at inference time — no full schema in prompt context.
Accepted NL-to-SQL RAG AI semantic layer Mar 2026 view .md →
007
Automated Governance Pipeline — Classification to Ranger TagREST
Automated pipeline: Privacera classifiers scan new tables → PII/PCI tags applied → Privacera policy engine propagates masking rules. No manual policy authoring for standard classification tiers.
Accepted Privacera governance automation Mar 2026 view .md →
008
Microsoft Fabric OneLake — Shortcuts and XTable Not Adopted
OneLake Shortcuts and XTable (Delta↔Iceberg conversion) evaluated and rejected. Shortcuts create a dependent path that bypasses Polaris credential vending. XTable conversion adds latency and format mismatch risk. Superseded by ADR-010.
Superseded Fabric OneLake → see ADR-010 Mar 2026 view .md →
009
AI Data Hub — RAG-Ready Data Serving Layer for the Lakehouse
Gold layer tables exposed to AI consumers via a Python FastAPI trust boundary enforcing certified query patterns. Direct Gold access prohibited for agent workloads — all AI queries must pass through the certified gateway.
Accepted AI hub FastAPI trust boundary Mar 2026 view .md →
010
Microsoft Fabric Import Semantic Model as BI and AI Surface Layer
Fabric Import mode (not DirectLake, not Shortcuts) is the correct BI/AI surface. Gold exists in two representations: Iceberg V2 on-prem (compute plane) and Delta copy in Fabric (BI/AI surface). Import mode is mandatory for PII/PCI tables — DirectLake bypasses T-SQL DDM enforcement.
Accepted Fabric Import mode ADR-010 DDM enforced Apr 2026 view .md →
