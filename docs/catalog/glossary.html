Trading

Trade

A financial transaction involving buying or selling a security, derivative, or other financial instrument. Trades have a trade date, settlement date, price, quantity, and counterparty.

Synonyms: transaction, deal, execution

Table: gold.trading_metrics

Technical Detail
Raw trade data arrives in bronze.raw_trades_history, is validated and standardized in silver.trades_validated, and aggregated in gold.trading_metrics.

View in OpenMetadata: /glossary/trade

notional_value

The total dollar value of a trade or position, calculated as price multiplied by quantity. Represents the gross market exposure for a given instrument.

Synonyms: gross value, face value, nominal value

Table: gold.trading_metrics

Technical Detail
Computed in gold.trading_metrics as price * quantity. Used in Cube semantic layer as the total_notional measure.

View in OpenMetadata: /glossary/notional-value

trade_count

The total number of individual trade executions in a given grouping (by symbol, side, time period). A core activity metric used for volume analysis.

Synonyms: execution count, transaction count

Table: gold.trading_metrics

Technical Detail
Aggregated in gold.trading_metrics as COUNT(*) grouped by symbol and trade_side. Exposed via Cube as trade_count measure.

View in OpenMetadata: /glossary/trade-count

average_price

The mean execution price across all trades for a given instrument and side. Used for cost basis analysis and execution quality monitoring.

Synonyms: avg price, mean price, VWAP

Table: gold.trading_metrics

Technical Detail
Calculated in gold.trading_metrics as AVG(price). Exposed via Cube as avg_price measure.

View in OpenMetadata: /glossary/average-price

Risk

Position

The amount of a security or financial instrument held by an entity at a specific point in time. A position is the net result of all trades in a given security. Can be long (owned) or short (borrowed and sold).

Synonyms: holding, exposure

Table: gold.risk_exposure

Technical Detail
Tracked daily in gold.risk_exposure. Source data flows from bronze.raw_positions_daily through silver.positions_validated.

View in OpenMetadata: /glossary/position

market_value

The current market value of a position, calculated as quantity multiplied by the current market price per unit. Used for portfolio valuation and risk reporting.

Synonyms: mark-to-market, fair value, current value

Table: gold.risk_exposure

Technical Detail
Computed in gold.risk_exposure as quantity * current_price. Mark-to-market exposure for daily risk snapshots.

View in OpenMetadata: /glossary/market-value

var_95

Value at Risk at 95% confidence level. The maximum expected loss over a specified time horizon such that there is a 95% probability the actual loss will not exceed this amount.

Synonyms: VaR 95, value-at-risk 95

Table: gold.risk_exposure

Technical Detail
Computed in gold.risk_exposure. A core risk metric required by BCBS 239 for risk reporting.

View in OpenMetadata: /glossary/var-95

var_99

Value at Risk at 99% confidence level. The maximum expected loss over a specified time horizon such that there is a 99% probability the actual loss will not exceed this amount.

Synonyms: VaR 99, value-at-risk 99

Table: gold.risk_exposure

Technical Detail
Computed in gold.risk_exposure. More conservative than VaR 95, used for stress testing and regulatory capital calculations.

View in OpenMetadata: /glossary/var-99

expected_shortfall

Expected Shortfall (Conditional VaR) measures the average loss in the tail beyond the VaR threshold. Captures the severity of tail risk events.

Synonyms: CVaR, conditional VaR, tail VaR

Table: gold.risk_exposure

Technical Detail
Computed in gold.risk_exposure. Considered a more coherent risk measure than VaR and increasingly required by regulators.

View in OpenMetadata: /glossary/expected-shortfall

position_count

The total number of open positions in a given grouping (by account, sector, currency). Used for portfolio concentration analysis and diversification monitoring.

Synonyms: holding count, open positions

Table: gold.risk_exposure

Technical Detail
Aggregated in gold.risk_exposure as COUNT(*). Used for capacity planning and concentration limits.

View in OpenMetadata: /glossary/position-count

Governance

PII

Personally Identifiable Information -- any data that could be used to identify a specific individual. Subject to data protection regulations including GDPR, CCPA, and industry-specific rules.

Synonyms: personal data, sensitive personal information

Technical Detail
PII columns are automatically classified via regex rules in Apache Ranger tag policies. Non-privileged users see masked values through column-level masking.

View in OpenMetadata: /glossary/pii

BCBS 239

Basel Committee on Banking Supervision Principles for Effective Risk Data Aggregation and Risk Reporting. Requires strong risk data aggregation capabilities and internal risk reporting practices.

Synonyms: Basel 239, RDARR principles

Technical Detail
The lakehouse supports BCBS 239 compliance through end-to-end data lineage tracking via OpenLineage/Marquez. Lineage is captured at the pipeline level.

View in OpenMetadata: /glossary/bcbs-239

SLA

Service Level Agreement for data delivery timeliness. Each dataset has a defined SLA specifying the expected update interval and thresholds for warning and critical status.

Synonyms: service level, timeliness requirement, data contract

Technical Detail
Default SLAs: Gold 24h expected / 48h critical, Silver 12h / 24h, Bronze 6h / 12h. SLA breaches trigger alerts via Grafana. Defined in freshness_tracker.py.

View in OpenMetadata: /glossary/sla

Data Freshness

The time elapsed since the last successful data update for a given dataset. Tracked per table using traffic-light SLA status: GREEN, YELLOW, RED.

Synonyms: data recency, data currency, data latency

Technical Detail
Freshness dashboards are visible in Grafana and the OpenMetadata catalog. Status is calculated by freshness_tracker.py.

View in OpenMetadata: /glossary/data-freshness

Business Unit

An organizational division or segment of the firm that operates with its own profit and loss responsibility. Used to partition data access and ownership.

Synonyms: division, department, desk

Technical Detail
Business units are used in Apache Ranger row-level security policies to restrict data access by organizational division.

View in OpenMetadata: /glossary/business-unit

Infrastructure

Bronze Layer

The first layer of the medallion architecture. Contains raw ingested data with minimal transformation -- primarily format conversion. Data preserves the original source schema.

Synonyms: raw layer, landing zone, staging layer

Technical Detail
Format conversion (CSV/JSON to Iceberg Parquet). Metadata columns added: source_system, ingestion_ts, batch_id. 7-year retention for regulatory compliance.

View in OpenMetadata: /glossary/bronze-layer

Silver Layer

The second layer of the medallion architecture. Contains cleansed, validated, and standardized data. Source-system quirks are resolved and FSDM schema conformance is enforced.

Synonyms: cleansed layer, conformed layer, standardized layer

Technical Detail
Validation includes date format normalization, NULL handling, type casting, and deduplication. Used for cross-source joins.

View in OpenMetadata: /glossary/silver-layer

Gold Layer

The third layer of the medallion architecture. Contains business-ready aggregated data, denormalized for analytical consumption. Optimized for BI tools, AI/ML, and API consumption.

Synonyms: business layer, serving layer, analytical layer

Technical Detail
Gold tables represent the single, governed copy of truth for business metrics. Served through Cube semantic layer and Trino SQL engine.

View in OpenMetadata: /glossary/gold-layer
