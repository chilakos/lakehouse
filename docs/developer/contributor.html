Contributor Guidelines

Branch Naming, PR Process, Code Style, Testing, and Commit Format

Branch Naming

Use the pattern feature/TICKET-description for feature branches, fix/TICKET-description for bug fixes, and docs/TICKET-description for documentation. Why: CI parses the branch prefix to route deployments to the correct environment (feature/ → dev, release/ → staging). Consistent naming also makes PR lists scannable.

Name Type Description
feature/DATA-123-add-risk-pipeline feature New pipeline or functionality
fix/DATA-456-null-trade-ids fix Bug fix with ticket reference
docs/DATA-789-api-reference docs Documentation changes
refactor/DATA-101-extract-base-class refactor Code restructuring without behavior change

PR Process

Follow this workflow for all changes: (1) Create a branch from main using the naming convention above. (2) Make changes, ensuring each commit is atomic and follows the commit format below. (3) Run pre-commit run --all-files locally before pushing. (4) Push your branch and create a PR with a clear title and description. (5) Wait for CI checks to pass (lint, unit tests, integration tests). (6) Request review from at least one team member. (7) Address review feedback, then squash-merge once approved. Why: Pre-commit catches style and security issues before CI, saving pipeline minutes. Squash-merge keeps main history clean and bisectable.

Code Style (ruff)

The project uses ruff for linting and formatting, configured in etl/pyproject.toml. Why: ruff replaces flake8 + isort + pyupgrade in a single tool with 10-100x faster execution. The selected rule sets catch real bugs (flake8-bugbear) and enforce modern Python patterns (pyupgrade).

Name Type Description
line-length setting 120 characters (configured in pyproject.toml)
target-version setting py311 -- Python 3.11 minimum
E, W rule set pycodestyle errors and warnings
F rule set pyflakes -- undefined names, unused imports
I rule set isort -- import sorting and grouping
N rule set pep8-naming -- class and function naming conventions
UP rule set pyupgrade -- modernize syntax for target Python version
B rule set flake8-bugbear -- common bug patterns and design problems
SIM rule set flake8-simplify -- simplifiable expressions and control flow

Testing Requirements

All new code requires tests. Use the appropriate pytest markers for test categorization. Run python3 -m pytest -m unit -x before pushing to catch failures early. Why: The -x flag stops on first failure for fast feedback. Markers let CI run fast unit tests on every PR and slow integration tests on merge to main.

Name Type Description
@pytest.mark.unit marker Unit tests -- no external services required. Run on every PR.
@pytest.mark.integration marker Integration tests -- requires Docker services running.
@pytest.mark.slow marker Slow-running tests -- benchmarks, large dataset processing.
@pytest.mark.snowflake marker Snowflake integration tests -- requires Snowflake credentials.

Pre-commit Hooks

The project uses pre-commit with hooks defined in .pre-commit-config.yaml. Install with pre-commit install after cloning. Run all hooks manually with pre-commit run --all-files. Why: Catches formatting, trailing whitespace, YAML/TOML syntax errors, secrets, and Terraform formatting before code reaches CI. Saves review cycles and pipeline minutes.

Name Type Description
ruff check --fix hook Lint Python files with auto-fix (astral-sh/ruff-pre-commit v0.9.6)
ruff format hook Format Python files (astral-sh/ruff-pre-commit v0.9.6)
trailing-whitespace hook Remove trailing whitespace from all files
end-of-file-fixer hook Ensure files end with a newline
check-yaml hook Validate YAML syntax
check-toml hook Validate TOML syntax
check-added-large-files hook Block files larger than 1000 KB (--maxkb=1000)
detect-secrets hook Scan for accidentally committed secrets (Yelp/detect-secrets v1.5.0)
terraform_fmt hook Format Terraform files (antonbabenko/pre-commit-terraform v1.96.3)

Commit Format

Use Conventional Commits format. Why: Enables automated changelog generation and makes git log scannable. The scope is optional but recommended for multi-package changes.

Name Type Description
feat(pipelines): add risk exposure gold pipeline feat New feature, endpoint, component, or pipeline
fix(quality): handle null values in reconciliation fix Bug fix or error correction
test(governance): add anomaly detector edge cases test Test-only changes -- new tests or test fixes
refactor(semantic): extract prompt building to module refactor Code cleanup with no behavior change
docs(developer): update API reference for v0.2 docs Documentation-only changes
chore(deps): upgrade ruff to v0.10.0 chore Config, tooling, or dependency changes
