Testing Guide

Unit tests, integration tests, markers, and CI gate behavior

1Test Organization

All tests live under etl/tests/. The conftest.py at the root provides session-scoped fixtures for Spark, Nessie, Trino, MinIO, and S3.

Directory Structure

  • etl/tests/ -- test root with conftest.py
  • etl/tests/unit/ -- unit tests (no external services)
  • etl/tests/integration/ -- integration tests (requires Docker services)
  • etl/tests/fixtures/ -- test data files (COBOL copybooks, sample CSVs)

Key Fixtures (conftest.py)

  • spark_session -- Session-scoped SparkSession configured for Iceberg/Nessie REST catalog. Skips if PySpark unavailable or Nessie unreachable.
  • nessie_url -- Nessie REST API base URL (default: http://localhost:19120)
  • minio_endpoint -- MinIO S3-compatible endpoint (default: http://localhost:9000)
  • trino_connection -- Trino DBAPI connection. Skips if Trino unreachable.
  • minio_client -- boto3 S3 client configured for MinIO.
  • s3_client -- boto3 S3 client for AWS. Skips if credentials unavailable.

2Pytest Markers

Four markers are defined in etl/pyproject.toml under [tool.pytest.ini_options]. The --strict-markers flag is enabled, so unregistered markers cause errors.

Marker Reference

Use these markers to categorize and selectively run tests.

3Marker Reference Table

  • unit -- Unit tests with no external services required. Run with pytest -m unit. These are the default CI gate tests.
  • integration -- Integration tests requiring Docker services (Nessie, MinIO, Spark, Trino). Run with pytest -m integration.
  • slow -- Slow-running tests (large datasets, full pipeline execution). Excluded from default runs. Run with pytest -m slow.
  • snowflake -- Snowflake integration tests requiring Snowflake credentials. Run with pytest -m snowflake. Skipped in CI by default.

4Running Tests

Common test invocations from the etl/ directory.

# Unit tests only (fastest, no Docker needed)
pytest tests/ -m unit -x --tb=short

# Integration tests only (requires Docker stack)
pytest tests/ -m integration -x --tb=short

# Full test suite (all markers)
pytest tests/ -x --tb=short

# Single test file
pytest tests/test_base_pipeline.py -x --tb=short -v

# Verbose output with coverage
pytest tests/ -m unit --cov=src --cov-report=term-missing -v

5CI Gate Behavior

The CI pipeline runs on every pull request to main, staging, and dev branches.

On Pull Request (ci.yml)

  • python-lint: Runs ruff check . and ruff format --check . in etl/
  • python-test: Runs pytest tests/unit/ -x --tb=short -- unit tests only, fast feedback
  • cube-yaml-validate: Validates Cube YAML structure and glossary links
  • terraform-validate: Runs terraform init -backend=false && terraform validate
  • terraform-fmt: Checks Terraform formatting with terraform fmt -check -recursive

On Merge to Dev/Staging/Prod

  • Full integration test suite runs against deployed environment
  • Staging deployment includes integration tests
  • Production deployment includes smoke tests (Nessie health, Trino health)

Handling CI Failures

  • Lint failure: Run ruff check --fix . && ruff format . locally, commit, push
  • Test failure: Run the failing test locally with -v --tb=long for full traceback
  • Terraform failure: Run terraform validate and terraform fmt -recursive in infra/terraform/

6Writing New Tests

Follow these conventions when adding tests.

File Naming

  • Test files: test_{module}.py (e.g., test_base_pipeline.py)
  • Place unit tests in tests/ or tests/unit/
  • Place integration tests in tests/integration/

Marker Decoration

Always apply the appropriate marker. Classes inherit markers from the class decorator.

import pytest

@pytest.mark.unit
class TestMyFeature:
    def test_basic_behavior(self):
        """Describe what this test validates."""
        result = my_function("input")
        assert result == "expected"

    def test_edge_case(self):
        with pytest.raises(ValueError, match="invalid"):
            my_function("")

Fixture Usage

Use conftest.py fixtures for integration tests. Fixtures skip gracefully when services are unavailable.

@pytest.mark.integration
def test_full_pipeline(spark_session):
    """End-to-end test with real Iceberg tables."""
    pipeline = MyBronzePipeline(spark_session, data, "test", "batch-001")
    result = pipeline.execute()
    assert result["rows_written"] > 0

Assertion Patterns

  • Use descriptive assertion messages: assert count > 0, f'Expected rows, got {count}'
  • For PySpark schemas, compare StructType objects directly
  • For quality results, check result['passed'] and result['critical_failures']
  • Mock external services in unit tests: @patch('src.pipelines.base.lit')
