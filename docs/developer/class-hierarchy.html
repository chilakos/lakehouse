BasePipeline Inheritance Tree and Supporting Classes

Design Philosophy

All ETL pipelines extend BasePipeline, which enforces the contract: extract → transform → validate_schema → quality_check → write. This abstract base pattern ensures schema validation and quality gates cannot be bypassed. The MedallionLayer enum (BRONZE, SILVER, GOLD) provides type-safe layer designation, while PipelineConfig encapsulates all pipeline metadata as a frozen dataclass.

Medallion Layers

Bronze pipelines (TradesBronzePipeline, PositionsBronzePipeline, MainframeBronzePipeline) ingest raw data from external sources with metadata columns (source_system, ingestion_ts, batch_id). Silver pipelines (TradesSilverPipeline, PositionsSilverPipeline) clean, deduplicate, and standardize Bronze data. Gold pipelines (TradingMetricsGoldPipeline, RiskExposureGoldPipeline) produce business-ready aggregations that cross source boundaries.

Adding a New Pipeline

To add a new pipeline: (1) Create a new class extending BasePipeline, (2) implement extract() to return a DataFrame from your source, (3) implement transform(df) to return the cleaned/transformed DataFrame, (4) define a PipelineConfig with target layer, table name, and schema. The base class handles schema validation, quality checks, and Iceberg writes automatically. See the First Pipeline Tutorial for a step-by-step example.

Supporting Classes

PipelineConfig (frozen dataclass) -- holds name, target_layer, target_table, target_schema, optional source_layer, quality checks path, critical checks list, and retry settings. Properties full_table_name and source_table_name compute Iceberg table paths. MedallionLayer (enum) -- BRONZE, SILVER, GOLD with string values. SchemaValidationError -- raised when DataFrame schema does not match target. QualityGateError -- raised when critical quality checks fail, blocking layer promotion. IncrementalConfig -- configuration for incremental/watermark-based extraction.
