Repository Structure

Directory layout and key files for the lakehouse platform

1Top-Level Overview

The repository is organized into six top-level directories, each owning a distinct concern.

lakehouse/
├── etl/              # Python ETL package: pipelines, governance, quality, config
├── docs/             # Documentation: SWOTs, architecture, developer guides (HTML)
├── infra/            # Terraform IaC for dev/staging/prod environments
├── semantic/         # Cube semantic layer YAML models and measures
├── ci/               # CI/CD scripts and GitHub Actions helpers
├── dbt/              # dbt models for Silver/Gold transformations (future)
├── .github/          # GitHub Actions workflows (ci.yml, deploy-*.yml)
├── docker-compose.yml   # 25+ services: Airflow, Trino, Nessie, MinIO, Ranger, etc.
└── pyproject.toml       # Python project config, pytest, ruff settings

2ETL Package Deep-Dive

The etl/ directory contains the core data pipeline framework.

etl/
├── src/
│   ├── pipelines/        # BasePipeline + Bronze/Silver/Gold implementations
│   │   ├── base.py           # Abstract BasePipeline, PipelineConfig, MedallionLayer
│   │   ├── bronze/           # TradesBronze, PositionsBronze, MainframeBronze
│   │   ├── silver/           # TradesSilver, PositionsSilver
│   │   ├── gold/             # TradingMetricsGold, RiskExposureGold
│   │   └── incremental.py    # IncrementalConfig for watermark-based ingestion
│   ├── config/           # Settings dataclass (environment, paths, credentials)
│   ├── governance/       # Data classification, freshness SLAs, audit logging
│   ├── quality/          # Soda quality checks, reconciliation engine
│   ├── semantic/         # NL-to-SQL engine, metric context builder
│   ├── iceberg_utils/    # Spark session factory, namespace management, maintenance
│   ├── lineage/          # OpenLineage Spark configuration
│   └── inventory/        # DataStage job inventory and complexity scoring
├── tests/              # pytest test suite (500+ unit tests)
│   ├── conftest.py       # Session fixtures, Spark mock, env defaults
│   └── test_*.py         # Test files matching source modules
└── pyproject.toml      # Package deps, pytest markers, ruff config

Package Import Paths

All internal imports use the src. prefix.

from src.pipelines.base import BasePipeline, PipelineConfig, MedallionLayer

3Documentation Directory

All documentation is rendered as standalone HTML from YAML data files via Jinja2 templates.

docs/
├── render_html.py        # Render pipeline: render_swots(), render_architecture(),
│                         #   render_developer_docs(), extract_versions(), extract_services()
├── templates/            # Jinja2 templates
│   ├── base_swot.html
│   ├── base_architecture.html
│   ├── base_developer.html
│   └── macros/           # Reusable macros: collapsible, code_block, checklist, etc.
├── swot/                 # SWOT analyses (YAML data + rendered HTML)
├── architecture/         # Architecture docs (YAML data + Mermaid diagrams + rendered HTML)
└── developer/            # Developer docs (YAML data + rendered HTML)

4Infrastructure

Terraform configurations for three environments.

infra/
├── main.tf             # Core infrastructure resources
├── variables.tf        # Environment-specific variables
├── terraform.tfvars    # Default variable values
└── modules/            # Reusable Terraform modules

5Key Files

Files you will interact with most frequently.

  • docker-compose.yml -- Defines all 25+ platform services with health checks and dependencies
  • etl/pyproject.toml -- Python deps, pytest config (markers: unit, integration, slow, snowflake), ruff linting rules
  • .pre-commit-config.yaml -- Pre-commit hooks: ruff format, ruff check, trailing whitespace, YAML/TOML validate, detect-secrets
  • docs/render_html.py -- Entry point for rendering all documentation to standalone HTML
  • .github/workflows/ci.yml -- CI pipeline: lint, test, validate Cube YAML, validate Terraform
