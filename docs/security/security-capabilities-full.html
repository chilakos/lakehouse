🔐 Domain 1 — Access Control (Table, Column, Row)
Who can see which data at what granularity. Privacera owns all of these.
Your list RBAC — Role-Based Access Control
Grant table access by role (ANALYTICS_TEAM can SELECT on finance.*). Baseline access control — who can see which tables and schemas.
Privacera · Polaris catalog RBAC (service accounts)
OSFI B-13 PCI Req 7
Your list Column-Level Security
Block or restrict access to specific columns entirely. Certain roles cannot even select sensitive columns.
Privacera (Spark via Kyuubi, Trino via SEP, Databricks via Privacera agent)
OSFI B-13 PCI Req 3,7
Your list Row-Level Security
Transparently inject WHERE clause predicates. CANADA_OPS only sees Canadian rows. Invisible to the user — query appears to return all data.
Privacera row filter policies
OSFI B-13 BCBS 239
New ABAC — Attribute-Based Access Control
Policies driven by user attributes (department, clearance level, jurisdiction) rather than explicit role assignment. More expressive than RBAC — policies like "employees in RISK_MGMT can see all PCI data where their cost_centre matches the data owner."
Privacera (tag + attribute policies) · Immuta (purpose-built ABAC)
OSFI B-13 Recommended for banking
New Purpose Limitation Enforcement
Enforce that data is only accessed for its declared purpose. A model training job cannot access live customer PII — it must use a synthetic or anonymised dataset. Policy: "ml_training role can only access anonymized tables, never raw PII tables."
Privacera tag-based policies · Immuta purpose-based access
OSFI B-13 Principle 8 PIPEDA
New Time-Based / Temporal Access
Restrict access to time windows. Month-end finance data locked after regulatory submission. Intraday trading data access restricted to market hours. Emergency access grants auto-expire after N hours.
Privacera scheduled policies · Custom policy conditions

🎭 Domain 2 — Data Masking & Transformation
Transform sensitive values at query time without blocking access. User sees data — but not the real data.
Your list Dynamic Data Masking (DDM)
Mask column values at query execution time. SIN → XXX-XXX-6789. Credit card → **** **** **** 4321. Partial reveal, full mask, or hash — policy-driven per role.
Privacera · Fabric SQL DDM (T-SQL) · Databricks Unity Catalog
PCI Req 3.5 OSFI B-13
New Format-Preserving Masking
Masked value looks structurally identical to real value — same length, same character types. A masked SIN still looks like a valid SIN. Critical for downstream systems that validate format without needing real values (analytics pipelines, model training).
Privacera FPE masking functions · Voltage SecureData (commercial)
PCI Req 3
New Data Tokenization
Replace sensitive values with non-sensitive surrogate tokens. Unlike masking (one-way), tokenization is reversible by authorized systems. PAN → TKN_4829af3c. The token is meaningless outside your vault. Detokenization requires explicit authorization and is logged.
Privacera Tokenization · Protegrity · Voltage (Micro Focus)
PCI DSS — removes data from scope
New Data Anonymization / Pseudonymization
Irreversibly remove identifying information (anonymization) or replace with pseudonyms (pseudonymization). Used for model training datasets and analytics where real identity is not needed. Anonymized data is outside PIPEDA scope.
Privacera anonymization policies · Dedicated pipeline step at Gold layer
PIPEDA OSFI B-13 Principle 8
New Differential Privacy
Add calibrated statistical noise to query results so individual records cannot be inferred. Useful for aggregate analytics on sensitive data where exact counts would reveal individuals. Used by Apple, Google for telemetry.
Google DP Library (OSS) · Custom query layer · Not in Privacera today
Emerging — OSFI AI guidelines
New Data Subsetting / Synthetic Data
Generate structurally identical but fictitious datasets for non-prod environments. Dev and test never touch real PII. Synthetic data preserves statistical distributions for model training without exposing real customer data.
Databricks DBRX Synthetic · Mostly AI · Gretel.ai · MDM synthetic generators
OSFI B-13 non-prod environments
🔒 Domain 3 — Encryption
Protect data at rest, in transit, and at the column level. Defense if storage is compromised.
New Encryption at Rest (TDE)
Encrypt all Parquet/ORC files on MinIO storage. AES-256 via MinIO Server-Side Encryption (SSE). Even if an attacker gets raw storage access, they get ciphertext. Keys managed separately from data.
MinIO SSE-KMS · HashiCorp Vault (key management) · AWS KMS via PrivateLink
PCI Req 3.5 OSFI B-13
New Encryption in Transit (TLS)
TLS 1.2+ on all network paths: engine ↔ Polaris REST, engine ↔ MinIO, engine ↔ Privacera, Privacera ↔ AD/LDAP (LDAPS), engine ↔ SIEM. Mutual TLS (mTLS) for service-to-service communication inside OCP.
OCP cert-manager · Polaris TLS config · MinIO TLS · Istio service mesh (mTLS)
PCI Req 4 OSFI B-13
New Column-Level Encryption (CLE)
Encrypt individual sensitive columns within Parquet files (e.g. Parquet Modular Encryption — PME). Column is stored encrypted; only engines with the column key can decrypt. Masking is at query time; CLE is at storage level — defense in depth for the most sensitive fields (PAN, SIN).
Apache Iceberg + Parquet Modular Encryption (PME) · Key management via Vault or AWS KMS
PCI Req 3 — strongest control for PAN
📋 Domain 4 — Audit Trail & Data Lineage
Who accessed what, when, from where — and how data flowed from source to consumer.
New Query-Level Audit Logging
Log every query: user, engine, tables accessed, columns projected, row filters applied, allow/deny decision, timestamp, client IP, query duration, rows returned. The full who-what-when-how record.
Privacera unified audit · Ranger Solr audit · Engine-native logs normalized to SIEM
PCI Req 10 OSFI B-13 Principle 10
New Column-Level Lineage
Track transformation history of every column from source system to Gold layer. Column X in the risk report traces back through Silver → Bronze → mainframe source. Mandatory for BCBS 239 data accuracy validation.
OpenLineage (Spark + Trino emitters) · Marquez or DataHub backend
BCBS 239 Principles 2,3,4,6
New Audit Log Integrity (WORM)
Audit logs must be tamper-proof — an attacker who gains access should not be able to delete their tracks. Write-Once-Read-Many (WORM) storage for audit logs. File integrity monitoring alerts on modification attempts.
MinIO WORM (Object Lock) · S3 Object Lock · Splunk immutable indexing
PCI 10.5.5 OSFI B-13
New Automated Audit Review (SIEM Alerting)
Automated rules detecting anomalous patterns: user accessing 10x normal data volume, access outside business hours, first-time access to PCI tables, failed access attempts, bulk exports. PCI 4.0 now mandates automated review — manual log review is not sufficient.
Splunk Enterprise Security · Elastic SIEM · Microsoft Sentinel
PCI 10.4.1 — mandatory in 4.0
🚨 Domain 5 — Data Loss Prevention (DLP)
Prevent sensitive data from leaving controlled environments — through exports, downloads, email, or API calls.
New Query Result Export Controls
Restrict or block export of query results above a threshold. Prevent SELECT * on PII tables being exported to CSV or downloaded via JDBC. Alert on unusually large result sets (potential data exfiltration). Privacera can block certain query patterns (e.g., full table scans on PII tables without a WHERE clause).
Privacera query-pattern policies · Fabric DLP policies · Network egress controls
OSFI B-13 Principle 8 PCI Req 3,7
New Data Watermarking
Embed invisible, user-specific identifiers in query results. If data leaks externally, the watermark identifies which user or system the data came from. Useful for detecting insider threats and accidental disclosure from analytical outputs.
Privacera Watermarking (commercial feature) · Specialized DLP tools
OSFI B-13 incident investigation
New Sensitivity Label Propagation
When a new table is derived from a PII-tagged source, the derived table automatically inherits the PII label. Prevents accidental label loss during transformations. A Gold aggregation of a PII source should stay labelled even if individual records are anonymised — until explicitly declassified.
Microsoft Purview auto-labelling · Privacera tag inheritance · Apache Atlas classification propagation
OSFI B-13 Principle 8
New Network-Level Egress Controls
OCP NetworkPolicy and firewall rules preventing data exfiltration at the network layer — independent of application-level controls. Even if an engine is compromised, raw Parquet data cannot be exfiltrated to unknown external IPs.
OCP NetworkPolicy · Firewall · MinIO bucket policies (deny cross-region)
OSFI B-13 PCI Req 1
🏷️ Domain 6 — Data Classification & Discovery
Know what sensitive data you have before you can protect it. Classification drives all other controls.
New Automated PII/PCI Discovery
Scan Iceberg tables for PII and PCI patterns (SIN, credit card PANs, dates of birth, addresses) using regex and ML classifiers. At tens of thousands of tables, manual classification is impossible — auto-discovery is mandatory.
Microsoft Purview data scanning · Privacera built-in classifiers · Apache Atlas classifiers · BigID
OSFI B-13 Principle 8 PCI Req 3 — know where PAN lives
New Data Classification Taxonomy
Formal tiered classification: PUBLIC · INTERNAL · CONFIDENTIAL · RESTRICTED · PCI · PII. Each tier has mandatory controls (encryption, masking, access restrictions). Classification is the metadata that drives Privacera's tag-based policies.
Apache Atlas classification types · Privacera sensitivity levels · Purview sensitivity labels
OSFI B-13 Principle 8
New Data Inventory & Catalogue Governance
Know every table, its owner, its classification, its retention period, its upstream sources. Without a data inventory you cannot demonstrate OSFI compliance — you cannot protect what you don't know exists.
Apache Atlas · DataHub · Collibra · Alation
BCBS 239 Principle 2 OSFI B-13
New Data Retention & Deletion
Enforce retention periods on Iceberg tables — automatically expire old snapshots, delete expired partitions. Support right-to-erasure (RTBF) requests for individual records via Iceberg V2 row-level deletes. Retention tied to classification tier.
Iceberg V2 row-level deletes · Iceberg snapshot expiry · Custom retention pipeline · Collibra policy enforcement
PIPEDA RTBF OSFI B-13
🗝️ Domain 7 — Credentials, Secrets & Key Management
Secure management of service credentials, API keys, encryption keys, and short-lived tokens.
New Secrets Management (Vault)
Centralized secret store for all service credentials: Polaris DB passwords, Privacera LDAP bind credentials, MinIO access keys, TLS certificates. Secrets injected into OCP pods at runtime via CSI driver — never baked into container images or ConfigMaps.
HashiCorp Vault · OCP Secrets Store CSI Driver · CyberArk Conjur
PCI Req 3,8 OSFI B-13
New Credential Vending (Short-lived STS tokens)
Polaris vends temporary, scoped storage credentials to engines at query time (15–60 min TTL). No long-lived credentials in engine configs. Scope is limited to the specific S3 prefix for the requested table. If credentials leak, they expire quickly and have minimal blast radius.
Apache Polaris credential vending · MinIO STS · AWS AssumeRole
PCI Req 3,7
New Encryption Key Management (KMS)
Separate key management from encrypted data. MinIO encryption keys stored in Vault KMS (not on MinIO itself). Key rotation on schedule. Key access logged. Envelope encryption: data encrypted with DEK, DEK encrypted with KEK stored in Vault.
HashiCorp Vault KMS · Thales Luna HSM · AWS KMS (cloud burst)
PCI Req 3.7 OSFI B-13
New Break-Glass / Emergency Access
Controlled procedure for emergency elevated access that bypasses normal RBAC. Every break-glass access is: pre-approved by defined authority, time-limited, fully logged, and generates a SIEM alert. Required for incident response without creating a permanent security backdoor.
Privacera temporary policy grants · CyberArk PAM · HashiCorp Vault dynamic secrets
OSFI B-13 incident response PCI Req 8
🪪 Domain 8 — Identity, Authentication & MFA
Verify that users and services are who they claim to be before granting any access.
New MFA for Privileged Access
Multi-factor authentication for Privacera admin, Polaris admin, SIEM admin, and any break-glass access. Standard AD SSO for regular analyst queries. MFA required for any administrative action that changes security policies.
RBC AD MFA · Keycloak MFA flows · CyberArk PAM
PCI Req 8.4 — mandatory for admin
New Service Account Governance
Every engine service account (Spark, Trino, Databricks) has a dedicated identity, minimum-privilege Polaris catalog role, and periodic access review. No shared service accounts. Service account credentials rotated on schedule via Vault. Stale accounts auto-disabled.
Polaris principal management · HashiCorp Vault dynamic credentials · CyberArk
PCI Req 8 OSFI B-13
New Privileged Access Management (PAM)
All administrative access to Polaris, Privacera, MinIO, and PostgreSQL goes through a PAM vault. Admins never have direct credentials — they check out a session through PAM with full session recording. PAM sessions are a key audit control for change management.
CyberArk PAM · BeyondTrust · HashiCorp Vault
PCI Req 8,10 OSFI B-13
🔍 Domain 9 — Query-Level Controls
Control not just what data users see, but how they can query it — preventing dangerous patterns.
New Query Pattern Restrictions
Block dangerous query patterns regardless of data sensitivity: SELECT * without WHERE on PII tables, full table scans on tables above a size threshold, JOINs that combine PII from two different classification tiers, downloads of more than N rows. Privacera can enforce these as policy rules.
Privacera query-level policies · Trino resource groups · Kyuubi query rate limiting
OSFI B-13
New Query Rate Limiting & Anomaly Detection
Detect and throttle abnormal query behaviour: a user running 10,000 queries in 5 minutes, an account suddenly accessing tables it has never touched, or queries returning 100x normal result size. Both a DLP control and an insider threat signal.
Privacera behaviour analytics · SIEM correlation rules · Trino resource groups
PCI 10.4.1 OSFI B-13 Principle 10
New Data Aggregation Minimum (k-Anonymity)
Enforce minimum group sizes in aggregation queries to prevent individual re-identification. A query returning COUNT=1 for a sensitive group reveals the individual. Policy: suppress any aggregate result where COUNT < k (e.g., k=5). Required when analytics consumers are external or semi-trusted.
Custom query post-processing · Trino query rewrite · Privacera result-set policies
PIPEDA Privacy by design
New Approved Query Patterns (Certified Queries)
For AI/agent consumers (RBC Assist), restrict access to a whitelist of pre-approved, certified query patterns via a FastAPI gateway. No ad-hoc SQL against Gold layer from agents — only certified parameterized queries. The trust boundary you described in your ADR architecture.
Python FastAPI middle layer (your existing ADR) · Privacera service account with narrow policy
OSFI B-13 BCBS 239
📝 Domain 10 — Data Change Management & Integrity
Ensure data changes are controlled, auditable, and reversible — especially for regulated datasets.
New Write-Audit-Publish (WAP) Workflow
No data goes directly to the production Gold layer without passing a validation gate. Write to staging/branch, run data quality checks (Soda, Great Expectations), compliance validation, then atomically publish to main. Enforces "four-eyes" principle on data changes.
Nessie branching · Iceberg snapshot isolation · Soda / Great Expectations quality gates
BCBS 239 Principle 3 — data accuracy
New Immutable Audit Snapshots
Tag Iceberg snapshots at regulatory reporting dates. The state of Gold layer on Dec 31 is preserved forever — any regulator inquiry can reproduce the exact dataset used for that reporting period. Iceberg time-travel makes this free operationally.
Iceberg snapshot tagging · Nessie tags · Polaris snapshot management
BCBS 239 OSFI B-13
New Schema Change Governance
Schema changes (adding columns, altering types) in Iceberg are atomic and logged as metadata commits. But you need a governance gate: schema changes to PCI-classified tables require a security review before being applied to production catalog. Automated CI/CD check before schema evolution.
Polaris schema evolution API · GitHub PR gate · Privacera schema sync re-run after change
