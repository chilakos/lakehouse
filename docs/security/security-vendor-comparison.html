RBC Recommendation — April 2026
First Choice: Immuta (self-hosted on OCP)
Immuta is the strongest candidate given the current Trust3 AI situation. Its engineering focus has not pivoted — the January 2026 release was a data security patch update. The September 2025 Trino performance improvement (4.26x) shows active investment in exactly the integration RBC needs most. Self-hosted Helm on OCP resolves the OSFI B-10 concern entirely. The ABAC policy model is more expressive than Ranger RBAC for complex jurisdictional access rules common in Canadian banking regulation.

The blocker is price. At ~$5k/user/month for a 150-person data org, this needs Rex and Joey involved before any POC commitment. The price signals enterprise procurement, not a tactical tool evaluation.
Conditional: Trust3 AI (self-hosted, with roadmap validation)
Trust3 AI is not disqualified — the Ranger-based data security platform is still sold and supported. The question is how much engineering investment it receives going forward. Before any procurement decision, RBC needs answers to three specific questions from Trust3 AI:

1. What is the roadmap for Polaris REST catalog schema sync as a supported integration?
2. Who owns the data security product engineering — and are they separate from the AI governance team?
3. What is the self-hosted deployment SLA and support commitment for on-prem Kubernetes?

Honest answers to these determine whether Trust3 AI is still viable or whether the AI rebrand has effectively orphaned the data security platform.
Fallback: OPA + Kyuubi (OSS)
If both commercial options fail the procurement or roadmap test, OPA + Kyuubi is a credible alternative for the on-prem Trino and Spark engines. Zero vendor risk, zero SaaS, zero lock-in. The gaps — no Databricks integration, no auto-classification, no self-service workflow, manual policy authoring in Rego — are real but manageable with engineering investment. The Polaris OPA integration (v1.3) means the catalog and enforcement plane speak to the same policy engine. This path requires staffing a small data security engineering team, not a third-party product.
Critical pre-decision action for all three paths: None of these vendors have a documented, tested integration with Apache Polaris REST catalog as a supported deployment. The specific question — “can your product sync schema and enforce column/row policies against tables served by Polaris REST API?” — needs a direct answer from each vendor before architectural lock-in. This is the most important unresolved integration point in the architecture.
